# 今日动作与每周安排

0.5.0，2026-10-18。

## 使用方法

首页计划卡下有两个入口：

- **编辑今日动作**：改变今天这一场计划的动作组成；七天切换选中未来日期时显示“编辑当天动作”。
- **编辑每周安排**：分别点开周一至周日，保存以后重复使用的安排。

编辑页可以改名称、选择力量日或轻活动日、按分区搜索并添加动作、删除动作、用上下箭头调整分区内顺序。卡片右侧调整按钮可改组数、每组次数/秒数和同类替换。可选有氧可单独开关。已加入的动作不重复提供；四个候选动作仍只供查阅，不开放加入。

改动先保留为草稿，点底部保存按钮才写入本地。返回时如有未保存修改，会提示放弃或继续编辑。页面重建会保留草稿。清空动作可保存为空休息日，此时首页不能开始空训练。

“恢复每周安排”清除这一天的独立修改，让它重新跟随每周模板；“恢复默认安排”清除对应星期的自定义模板。这两个操作同样需要点底部保存。恢复后再手动修改草稿，会保存为新的自定义安排。

## 生效范围

优先级：当天独立修改 → 对应星期模板 → 内置默认计划。

模板保存时记录生效日期，只用于该日期及以后的对应星期。已经独立编辑的日期不会被模板覆盖，需要在当天编辑页恢复跟随。过去日期仅供查看。训练开始时保存完整快照，后来修改模板不会改变进行中的训练或历史记录；进行中暂时不允许编辑当天计划，每周模板仍可编辑。

每周安排逐日保存，没有“一键覆盖七天”或跨分区拖动。若需把一个动作移到别的适用分区，可先删除再添加。组数维持 1–5；次数维持 1–30，计时动作维持 1–120 秒。编辑动作后时长取决于实际内容，因此首页不再对所有自定义计划显示固定的时长估计。

## 数据与兼容

- 新增 Room `week_templates` 表，以星期（1–7）为主键，保存名称、类型、动作列表和生效日期。
- 原 `plans` 表继续保存具体日期的独立修改；`workouts` 保存训练快照。
- 数据库从版本 1 升级至版本 2，只新增表，不清空或重建旧表。应用显式注册 `MIGRATION_1_2`，没有 destructive migration fallback。
- 空计划可保存，但仓库层和页面均阻止创建空训练。
- 计划、模板及记录加载完成后才开放首页，避免首次载入期间使用临时默认计划。

实现入口：`PlanEditor.kt`、`MainActivity.kt`；解析规则：`Training.kt`；持久化及迁移：`Storage.kt`。本版验证详见 `VALIDATION-0.5.0.md`。
